## [프로젝트] AUGraphics 검수 자동화 툴 — 게임 아바타 아이템 End-to-End 검수 파이프라인

### 프로젝트 개요

게임 아바타 아이템(의상/악세사리)의 3D 그래픽 품질 검수를 전 과정 자동화한 Windows 데스크탑 애플리케이션. 압축 파일 수신 → 파일명 검증 → 게임 클라이언트 자동 제어 → **Vision-Language Model(VLM) 기반 멀티모달 결함 탐지** → 3ds Max 자동 연동 → 검수 결과 엑셀 자동 기록까지 End-to-End 파이프라인을 단독 설계 및 구축.

- **개발 기간**: ____년 __월 ~ ____년 __월 (약 __개월)
- **담당 역할**: 단독 개발 (기획·설계·구현·운영 전담)
- **형태**: Windows EXE (C# WinForms / .NET 8.0)

## End-to-End 자동화 파이프라인

### VLM→MAX 모드
```
압축 파일 자동 탐지/해제
  → 파일명 검증 및 자동 교정 (RGM/DDS 파츠 접두사 불일치 rename)
  → 게임 클라이언트 자동 제어: OCR 좌표 캐싱 → 아이템 로드 → 크래시 체크
  → 멀티모달 VLM 결함 탐지: 4각도 캡처 → 업스케일 → VLM 추론 → 결과 엑셀 기록
  → 3ds Max Clean & Fix 배치 실행 (MaxScript 자동화)
  → RGM Export → Pass 2 재검수
  → 결과 엑셀 타임스탬프 저장
```

### MAX→VLM 모드
```
압축 파일 자동 탐지/해제
  → 파일명 검증 및 자동 교정
  → 3ds Max Clean & Fix 배치 실행
  → 게임 클라이언트 자동 제어: 크래시 체크
  → 멀티모달 VLM 결함 탐지
  → RGM Export → Pass 2 재검수
  → 결과 엑셀 타임스탬프 저장
```

## 주요 기능 상세

### 1. 압축 파일 자동 처리

- inspection 폴더 내 ZIP/ALZ 파일 자동 탐지 및 순차 처리
- ZIP 파일명 인코딩 자동 판별: UTF-8(베트남 시스템) / CP949(한국 PC) 모두 정상 처리
- 처리 완료 후 압축 파일은 `original_zip` 폴더로 이동, 해제 폴더는 `completed`로 이동

### 2. 파일명 자동 교정 및 검증

- AVATAR 폴더 복사 직후, 엑셀 검증 전에 실행
- RGM 파일명과 DDS 파일명의 파츠 접두사 불일치 시 자동 교정
  - 예: `mp_n24993.RGM` + `mj_n24993.dds` → `mj_n24993.RGM`으로 rename
- DDS 파일명이 `m_` / `f_` 단독(파츠 이니셜 없음)이면 교정 건너뜀
- 교정 결과가 엑셀 검증 단계에도 반영됨

### 3. PaddleOCR 기반 UI 좌표 자동 인식 및 캐싱

- 실행 시작 시 PaddleOCR PP-OCRv5로 게임 클라이언트 화면 1회 스캔, 세션 동안 좌표 재사용 (반복 OCR 호출 제거)
- 캐싱 대상: Character Reset, Item Reload, MAN/Female 버튼, 검색 버튼, Race 선택, VLM 전용 버튼(Motion List, 000.RGM, Front/Back/Left/Right 등)
- 해상도 독립적 동적 좌표 추출 — 하드코딩 좌표 대비 환경 변화에 강건한 구조

### 4. CharTool 크래시 체크 자동화 (Pass 1)

- Female → Male → 악세사리 순으로 아이템 검수
- 성별 전환 시: Character Reset → Item Reload → 성별 클릭 (세션 내 1회)
- 악세사리: 매 아이템마다 Character Reset → Item Reload → MAN 클릭 후 검색
- 각 아이템 더블클릭 → 3.5초 대기 → 응답 없음/크래시 확인
- `_w.dds` / `_b.dds` 파일 존재 시 인종색 추가 크래시 체크 (Race _w / Race _b)
- 크래시 발생 시: 엑셀 오류 기록 → CharTool 자동 재시작 → 해당 아이템 건너뜀
- 크래시 없음 시 엑셀 E열(크래시/오기입결과)에 "크래시 없음" 기록

### 5. Vision-Language Model(VLM) 기반 멀티모달 결함 탐지

- 크래시 없는 아이템에 한해 Front/Back/Left/Right 4각도 캡처 (8장: 착용/미착용)
- 원격 GPU 서버 REST API로 업스케일 전처리 후 VLM 추론 요청
- **업스케일 서버 장애 시 자동 재시도 (30초 대기 루프, CancellationToken으로 즉시 중단)**

**2단계 멀티모달 검사 (각도당)**

| 단계 | 입력 | 검사 항목 |
|------|------|----------|
| 1단계 | 미착용 단독 이미지 | 메쉬 파손, 텍스처 파괴, 머리캡 노출 |
| 2단계 | 착용/미착용 좌우 병합 이미지 | 피부 비침(A), 소매 검은 층 분리(B), 발 미노출(C) |

- 1단계 ABNORMAL 시 2단계 생략, bbox 이미지 자동 저장
- **프롬프트 엔지니어링**: 검사 항목별 독립 프롬프트 설계로 오탐(FP)/미탐(FN) 최소화
- 이상 감지 시 bbox 이미지 저장, F열(VLM코멘트) 자동 기록
- 전체 처리 완료 후 ABNORMAL 요약 txt 자동 생성

### 6. 3ds Max Clean & Fix 자동화 연동 (Pass 1)

- MaxScript(`test_clean_and_fix.ms`) 경로를 동적 치환 → 임시 .ms 파일 생성 → 3dsmaxbatch.exe 배치 실행 → 임시 파일 정리
- `.max` 파일마다: 바이패드 미연결 오브젝트 삭제, 텍스처 기준 잘못된 파츠 삭제, 오브젝트 이름 교정 후 덮어저장
- 처리 결과 CSV를 C#에서 직접 파싱, 검수요청 엑셀 I/J열에 자동 기록
- **처리 성능**: 파일당 평균 ~0.4초, 1,000개 기준 약 7분 소요

### 7. 3ds Max RGM Export 자동화 연동 (Pass 2)

- `.max` 파일 없으면 Pass 2 전체 자동 스킵
- MaxScript 배치 실행으로 Physique/Skin + Bip01 선택 → Export Selected → `.RGM` 자동 생성
- 최대 3회 자동 재시도 (실패 복구 로직)
- **처리 성능**: 파일당 평균 ~1.2초, 1,000개 기준 약 20분 소요

### 8. 엑셀 자동 기록

실행 시작 시 검수요청 엑셀에 D~J 7개 열을 1회 자동 삽입 후, 각 단계 결과를 고정 열에 기록.

| 열 | 내용 |
|---|---|
| D (체크) | 아이템 완료 시 `V` 기입 |
| E (크래시/오기입결과) | 크래시 없음 / 크래시 목록 / 파일명 오기입 내용 |
| F (VLM코멘트) | VLM 비정상 판정 내용 요약 |
| G (문제이미지) | 비정상 캡처 이미지 경로 |
| H (리소스툴결과) | 리소스툴 검사 결과 |
| I (MAX경로) | MAX Clean&Fix 대상 파일 경로 |
| J (MAX결과) | MAX Clean&Fix 오브젝트별 처리 결과 상세 |

- Pass 2 결과: E열에 `(rgm변환)` 접미사로 이어 기록
- 중지 또는 완료 시 `{원본파일명}_검수완료_{타임스탬프}.xlsx`로 inspection 폴더에 자동 저장

### 9. 이어하기 기능 (Resume Mode)

중지된 검수를 이어서 재개하는 기능. UI에서 **이어할폴더** + **이어할엑셀** 선택 후 실행 시 동작.

| 단계 | 일반 모드 | 이어하기 모드 |
|---|---|---|
| 압축 해제 | O | 스킵 — 선택한 폴더 직접 사용 |
| 파일명 검증 | O | 스킵 |
| 리소스툴 검사 | O | 스킵 |
| 이미 완료된 아이템 | 재처리 | D열(체크)에 `V` 있으면 스킵 |
| MAX 실행 | O | J열(MAX결과)에 값이 1개라도 있으면 전체 스킵 |

- 둘 중 하나만 선택 시 경고 팝업 표시 후 중단
- MAX 스킵 판단: J열 전체에 비어있지 않은 셀이 하나라도 있으면 MAX 배치 전체를 스킵

## 개선 과정 및 성과

#### 문제 1: 열 중복 삽입

| 구분 | 내용 |
|------|------|
| **증상** | VLM 이상 아이템이 여러 개일 때 엑셀에 열이 무수히 생성됨 |
| **원인** | 아이템마다 비고 열 좌우에 열 삽입 여부를 매번 체크하는 로직 — 삽입 후에도 헤더 확인 조건이 계속 참이 됨 |
| **해결** | `_vlmColumnsSetup` 플래그 도입 — 최초 1회만 열 삽입 여부 체크, 이후 전체 스킵 |

#### 문제 2: 악세사리 검수 순서 오류

| 구분 | 내용 |
|------|------|
| **증상** | 악세사리 아이템 검수 시 CharTool 초기화(CharReset/ItemReload/MAN) 없이 바로 다음 아이템 검색 |
| **원인** | 기존 초기화 로직이 성별 전환 시에만 동작하도록 설계됨 — 악세사리는 모두 MAN 고정이라 전환 감지 안 됨 |
| **해결** | 악세사리 루프 내 매 아이템 진입 시마다 CharReset → ItemReload → MAN 클릭 강제 실행 |

#### 문제 3: RGM 파일명 교정 오탐

| 구분 | 내용 |
|------|------|
| **증상** | `mp_n24993.RGM` + `m_n24993.dds` 조합에서 DDS가 `m_` 단독임에도 RGM 파일명이 교정됨 |
| **원인** | DDS 접두사 필터링 없이 무조건 교정 시도 |
| **해결** | DDS 접두사가 `m_` 또는 `f_` 단독(파츠 이니셜 없음)이면 교정 스킵 조건 추가 |

#### 문제 4: 재시도 시 기존 진행 결과 유실

| 구분 | 내용 |
|------|------|
| **증상** | 3ds Max 실행 중 크래시 후 재시도 시 이전 처리 결과 CSV가 초기화됨 |
| **원인** | 스크립트 시작 시 `createFile`로 무조건 덮어쓰기 |
| **해결** | `progressFile` 존재 여부 먼저 확인 → 재시도 시 append 모드로 열고 이어서 처리 |
