## [프로젝트 1] AUGraphics — 3D 아바타 그래픽 결함 자동 검수 시스템

### 프로젝트 개요

게임 아바타(캐릭터) 의류/아이템의 3D 그래픽 결함을 **Vision-Language Model(VLM) 기반 멀티모달 AI**를 활용하여 자동으로 검수하는 End-to-End 자동화 파이프라인. 압축 파일 수신부터 결과 엑셀 저장까지 전 과정을 단독 설계·구현.

- **개발 기간**: ____년 __월 ~ ____년 __월 (약 __개월)
- **담당 역할**: 단독 개발 (기획·설계·구현·운영 전담)

### 기술 스택

- **Language**: C# (.NET 8.0)
- **Framework**: Windows Forms
- **Excel 처리**: ClosedXML 0.102.2
- **AI/ML**: VLM (Qwen VL 32B), OCR (PaddleOCR PP-OCRv5)
- **3D 툴 연동**: 3ds Max 2020 (MaxScript, 3dsmaxbatch.exe)
- **압축 처리**: SharpCompress (ALZ), System.IO.Compression (ZIP, CP949/UTF-8 자동 판별)
- **Win32 API**: 윈도우 핸들 제어, 화면 캡처, 마우스/키보드 자동화
- **Infrastructure**: 원격 GPU 서버 (업스케일, VLM 추론)
- **개발 도구**: Claude Code (Anthropic)

### 시스템 아키텍처

| 단계 | 내용 |
|------|------|
| 1. 압축 파일 자동 탐지 | inspection 폴더 내 ZIP/ALZ 자동 탐지, CP949/UTF-8 인코딩 자동 판별 후 해제 |
| 2. 파일명 검증 및 교정 | 로컬 파일 vs 엑셀 파일명 비교, RGM/DDS 파츠 접두사 불일치 시 자동 rename |
| 3. 게임 클라이언트 자동 제어 | OCR 기반 UI 좌표 1회 캐싱, 아이템 로드 → 크래시 체크 → 4각도 캡처 (8장) |
| 4. 이미지 전처리 파이프라인 | 원격 GPU 서버 업스케일 API 호출, 착용/미착용 이미지 좌우 병합 |
| 5. VLM AI 결함 분석 | 각도별 2단계 검사 (단독 이미지 → 비교 이미지), 결함 유형별 bbox 이미지 저장 |
| 6. 3ds Max 자동 연동 | Clean & Fix (불필요 오브젝트 삭제·이름 교정) → RGM Export → Pass 2 재검수 |
| 7. 결과 엑셀 자동 기록 | D~J 7개 고정 열에 크래시/VLM/MAX 결과 기록, 완료 시 타임스탬프 파일로 저장 |

### 주요 기능 상세

**1. 압축 파일 자동 탐지 및 처리**
- inspection 폴더 내 ZIP/ALZ 자동 탐지 및 순차 처리
- ZIP 인코딩 자동 판별: CP949(한국 PC) / UTF-8(베트남 시스템) 모두 정상 처리
- 처리 완료 후 압축 파일은 original_zip 폴더로 이동, 해제 폴더는 completed로 이동
- 다음 압축 파일 존재 시 3초 대기 후 자동 연속 처리

**2. 게임 클라이언트 자동화**
- Win32 API 기반 윈도우 제어
- PaddleOCR 연동 UI 텍스트 인식 (한글 지원)
- 좌표 기반 마우스 클릭/드래그 자동화
- 회전 드래그 중 다각도 이미지 캡처 (8장)

**3. 이미지 전처리**
- 원격 GPU 서버 기반 해상도 업스케일 (VLM 전송 전 처리)
- 착용/미착용 이미지 좌우 병합 (2단계 비교 검사용)
- 업스케일 서버 연결 실패 시 30초 대기 후 자동 재시도 (중지 버튼으로 즉시 취소)

**4. Vision-Language Model(VLM) 기반 멀티모달 결함 탐지**

각도(Front/Back/Left/Right)별 2단계 멀티모달 검사:

| 단계 | 입력 | 검사 항목 |
|------|------|----------|
| 1단계 | 미착용 단독 이미지 | 메쉬 파손, 텍스처 파괴, 머리캡 노출 |
| 2단계 | 착용/미착용 좌우 병합 이미지 | A: 피부 비침, B: 소매 검은 층 분리, C: 발 미노출 |

- **프롬프트 엔지니어링**: 검사 항목별 독립 프롬프트 설계, 반복 테스트를 통한 오탐(FP)/미탐(FN) 최소화
- 원격 GPU 서버 REST API 기반 업스케일 전처리 → VLM 추론 파이프라인
- ABNORMAL 판정 시 bbox 이미지 자동 저장, 결과 엑셀 자동 기록
- 서버 장애 시 자동 재시도 로직 (CancellationToken 기반 즉시 중단 지원)

**5. 결과 자동 기록**
- 검수요청 엑셀에 D~J 7개 열 자동 삽입 (실행 시 1회), 각 단계 결과를 고정 열에 기록
- ABNORMAL bbox 이미지 캡처 폴더 저장 + 검수결과.txt 자동 생성 (ABNORMAL 요약 포함)
- 완료/중지 시 `{원본파일명}_검수완료_{타임스탬프}.xlsx`로 inspection 폴더에 자동 저장

## [프로젝트 2] AUControl — 게임 윈도우 AI 자동화 제어 플랫폼

### 프로젝트 개요

Audition 게임의 윈도우를 원격으로 제어하는 Windows 자동화 애플리케이션. 게임 보안(안티치트)을 우회하는 다양한 캡처/입력 방식과 **OCR·VLM 등 AI 기반 UI 인식**을 통합한 종합 자동화 플랫폼. C# 클라이언트 + Python OCR 서버의 **클라이언트-서버 분리 아키텍처**로 설계.

- **개발 기간**: ____년 __월 ~ ____년 __월 (약 __개월)
- **담당 역할**: 단독 개발 (설계·구현·운영 전담)

### 기술 스택

- **Language**: C# (.NET 8.0), Python 3.x
- **Framework**: Windows Forms
- **Graphics**: DirectX 11, DXGI Desktop Duplication API, SharpDX
- **AI/ML**: OCR (PaddleOCR, Tesseract, EasyOCR, Surya), VLM (Florence-2, LLaVA, QWEN VL, Google Gemini)
- **Image Processing**: OpenCV (OpenCvSharp4)
- **Data Processing**: EPPlus (Excel)
- **Win32 API**: 윈도우 제어, SendInput, PostMessage

### 주요 기능 상세

**1. 다중 화면 캡처 방식**

| 방식 | 특징 | 게임 호환성 |
|------|------|------------|
| PrintWindow | 기본 Win32 API | 일부 게임 |
| BitBlt | GDI 기반 | 일부 게임 |
| **DXGI** | DirectX 11 기반 | 안티치트 우회 |

- DXGI Desktop Duplication으로 게임 보안(Xigncode 등) 우회
- SharpDX 라이브러리 활용

**2. 다중 입력 시뮬레이션**
- SendInput API: 시스템 레벨 입력
- PostMessage: 윈도우 메시지 기반
- Interception Driver: 드라이버 레벨 입력 (안티치트 우회)
- 한글 입력 변환 (두벌식 → 영문 키 시퀀스)

**3. PaddleOCR 기반 AI 서빙 서버 설계 및 구현 (핵심 개선)**

- **클라이언트-서버 분리 아키텍처**: C# 클라이언트 ↔ Python OCR 서버(Port: 5123) HTTP REST 통신
- PaddleOCR 모델 서버 시작 시 1회 로드 후 메모리 상주 — 매 호출마다 모델 로드하는 방식 대비 추론 지연 최소화
- GPU/CPU 자동 감지 (CUDA 컴파일 여부 확인), GPU 가속 추론 지원
- 한글 특화 모델: `korean_PP-OCRv5_mobile_rec`

**REST API 엔드포인트**

| 엔드포인트 | 메서드 | 기능 |
|------------|--------|------|
| `/health` | GET | 서버 상태 확인 (GPU 여부) |
| `/ocr_image` | POST | Base64 이미지 OCR 처리 |
| `/find` | POST | 특정 텍스트 좌표 검색 |
| `/check` | POST | 텍스트 존재 여부 확인 |
| `/template` | POST | 템플릿 매칭 (OpenCV) |
| `/capture` | GET | 게임 화면 캡처 |
| `/ocr_with_scale` | POST | 확대 후 OCR (정밀 인식) |

**텍스트 매칭 알고리즘 (4단계)**
1. 정확히 일치
2. target이 text에 포함
3. text가 target에 포함 (70% 이상)
4. 유사도 비교 (SequenceMatcher)

**OCR 엔진 비교**

| 엔진 | 특징 | 속도 |
|------|------|------|
| **PaddleOCR** | GPU 가속, 한글 우수 | 가장 빠름 |
| Tesseract | 오프라인, 경량 | 중간 |
| EasyOCR | 다국어 지원 | 느림 |
| Surya | 최신 모델 | 중간 |

**4. Vision AI 기반 UI 분석**
- Florence-2: Vision Transformer 기반 좌표 추출
- LLaVA: 자연어 기반 UI 요소 설명
- 템플릿 매칭: OpenCV 기반 이미지 매칭
- 색상 검출: HSV 기반 UI 요소 탐지

**5. 자동화 엔진 (AutomationEngine)**
- 자연어 프롬프트를 액션으로 변환
- 멀티스텝 작업 순차 실행
- 조건부 분기 처리
- 에러 복구 로직

### AI 코딩 어시스턴트 협업 (Claude Code)

- **도구**: Claude Code (Anthropic) — 터미널 기반 AI 페어 프로그래밍 도구
- **활용 방식**: 버그 원인 분석, End-to-End 파이프라인 설계, 구현 검토를 AI와 협업하여 개발 속도 향상

**적용 사례**

1. **ZIP 인코딩 버그 수정**
   - 증상: EUC-KR(CP949) 인코딩 ZIP 파일의 한글 파일명이 깨지는 현상
   - 원인 분석: SharpCompress의 Latin-1 기본 인코딩 → ZipFile(CP949) 방식으로 전환
   - 결과: 기존 ZIP 호환성 유지하면서 신규 한글 ZIP 처리 가능

2. **컨테이너 폴더 감지 로직 구현**
   - 증상: 상위 그룹 폴더(예: "베트남")를 아이템 폴더로 오인식하여 0개 처리
   - 원인 분석: isItemFolder 판별 조건 부재
   - 결과: 폴더 구조 자동 판별 로직 추가로 정확한 아이템 폴더만 처리

3. **VLM 프롬프트 최적화**
   - 27회 이상 반복 테스트를 통한 프롬프트 엔지니어링
   - FP(정상 오탐)/FN(비정상 미탐) 원인 분석 및 단계적 개선
   - AI와 결과 데이터를 공유하며 근거 기반 수정 방향 도출
