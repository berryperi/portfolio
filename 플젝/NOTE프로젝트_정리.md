## [프로젝트] Note Generator — AI 기반 리듬게임 채보 자동 생성 시스템

### 프로젝트 개요

OGG/WAV 오디오 파일에서 Conformer 딥러닝 모델을 활용하여 리듬 게임의 채보(악보/노트)를 자동 생성하는 웹 기반 AI 시스템. 오디오 전처리 → 딥러닝 추론 → 다중 포맷 출력까지 **End-to-End AI 파이프라인**을 설계·구현. Docker 컨테이너 기반 GPU 서빙 환경으로 배포.

## 기술 스택 상세

### 딥러닝 / AI

| 기술 | 상세 내용 |
|------|----------|
| PyTorch | GPU 기반 딥러닝 프레임워크 (CUDA 12.1) |
| Conformer | 음성 인식 기반 신경망 아키텍처 — Multi-Head Self-Attention, Convolution Module, Feed Forward Network, 17개 인코더 레이어, 8개 어텐션 헤드 |
| MelBandRoformer | 보컬/MR 분리 AI 모델 |

### Conformer 모델 아키텍처

```
입력: Mel-Spectrogram (128 멜 밴드, 50-17000Hz)
  ↓
Positional Embedding (상대적 위치 인코딩)
  ↓
ConformerEncoder (17 layers)
  └── Feed Forward Module (1/2)
       ↓
      Multi-Head Self-Attention (8 heads)
       ↓
      Convolution Module (kernel=31)
       ↓
      Feed Forward Module (1/2)
       ↓
      Layer Normalization
  ↓
Fully Connected Layer (음표 클래스 예측)
  ↓
출력: Log-Softmax (음표 종류별 확률)
```

## 시스템 아키텍처

### End-to-End AI 파이프라인

| 단계 | 내용 |
|------|------|
| 1. 오디오 업로드 | .ogg/.wav 파일 입력 (최대 10개 다중 처리) |
| 2. 파일명 파싱 | BPM 자동 추출 (예: 곡명_Bpm-135.ogg → 135 BPM) |
| 3. 보컬 분리 (선택적) | MelBandRoformer 모델로 보컬/MR 분리 |
| 4. 오디오 전처리 | 리샘플링, Mel-Spectrogram 변환 (128 밴드), 1/16 박자 프레임 단위 분할 |
| 5. 배치 추론 | 패딩(동일 길이 정규화), GPU 텐서 변환, CUDA 가속 배치 처리 |
| 6. Conformer 모델 추론 | 17개 인코더 레이어, Self-Attention + Convolution, 음표 클래스 예측 |
| 7. 후처리 | 숨쉬기 규칙(쉼표 삽입), 확장 마디 처리, 음표 시퀀스 정리 |
| 8. 다중 포맷 변환 | MIDI 생성, TXT(별찌), MIDI→SLK(비트업/리듬홀릭), MIDI→XLS(원투파티) |
| 9. ZIP 아카이브 자동 생성 | 결과 파일 일괄 압축 |
| 10. 웹 UI 다운로드 제공 | Gradio 기반 실시간 진행 상태 표시 + 다운로드 |

### 지원 게임 모드

|----------|----------|----------|------|

## MIDI 포맷 상세

### MIDI 기본 상수

| 상수 | 값 | 설명 |
|------|-----|------|
| TPQ | 480 | Ticks Per Quarter (MIDI 표준) |
| TIME_UNIT | 120 | 1/16 박자 단위 (480 ÷ 4) |
| VELOCITY | 100 | 음표 세기 (0-127) |
| CHANNEL | 0 | MIDI 채널 |
| ADD_OFFSET | 24 | 1.5 박자 오프셋 |

### 음표 매핑 (MIDI 노트 번호)

**비트업/리듬홀릭**: `MELODY = [57, 60, 0, 62, 64, 0, 65, 67, 0, 69]`

**원투파티**:
- 60: `c` (Center)
- 59: `n` (Normal)
- 57: `s` (Space)
- 62: `d` (Down)
- 67: `r` (Right)

## 배포 환경 — Docker 컨테이너 기반 GPU 모델 서빙

PyTorch + CUDA + Gradio 구성의 환경 의존성 복잡도를 해소하기 위해 Docker 컨테이너로 패키징하여 배포. NVIDIA Container Toolkit을 활용한 GPU 패스스루로 **컨테이너 환경에서 GPU 가속 추론** 구현.

| 항목 | 내용 |
|------|------|
| 베이스 이미지 | pytorch/pytorch:2.x.x-cuda12.1-cudnn8-runtime |
| 노출 포트 | 7828 (Gradio 웹 인터페이스) |
| GPU 접근 | NVIDIA Container Toolkit (nvidia-docker2) |
| 모델 파일 관리 | 볼륨 마운트 (호스트 경로 → /app/models) |
| 환경 변수 | CUDA_VISIBLE_DEVICES, GRADIO_SERVER_PORT 등 |

### Docker Compose 구성 (GPU 패스스루)

```yaml
services:
  note-generator:
    build: .
    ports:
      - "7828:7828"
    volumes:
      - ./models:/app/models      # 학습 모델 (.pth) 마운트
      - ./output:/app/output      # 생성 파일 저장
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
```

**배포 방식의 장점**
- 환경 이식성: CUDA 버전, Python 패키지 의존성 충돌 없이 어느 서버에서나 동일 실행
- 모델 분리: 대용량 .pth 파일을 볼륨으로 분리하여 이미지 빌드 시간 및 용량 절감
- GPU 격리: 컨테이너별 GPU 리소스 독립 할당 가능
- 재현 가능성: 개발 환경과 운영 환경의 완전한 일치 보장
